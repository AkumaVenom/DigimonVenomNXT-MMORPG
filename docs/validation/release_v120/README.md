# Digimon Venom NXT v1.2.0 validation

The final complete suite finished with **2,683 passed, 10 skipped, no failures**
in **373.23 seconds** on Linux / Python 3.12.14. See `pytest_full.txt` for the
complete result and `release_checks.json` for runtime versions and scope.

The ten skipped checks are nine graphical Tk setup-wizard cases requiring a
desktop/Xvfb and one opt-in live-MySQL runtime check. Actual Windows executable
building, production database migration and live deployment were not performed
on this Linux host. The Windows build's package and launcher paths were checked
through its existing automated build simulation; no simulated executable is
included in the deliverable.

## Release coverage

- All **404 world maps** were exercised through real engine travel, encounter
  and flee operations with the Shiny roll selected server-side. All **502 Shiny
  species** were encountered in an eligible habitat, across both map families.
- Boundary and complete probability-bin checks cover one, two and three enemies:
  exactly 1% of bins choose Shiny and 2.5% choose Paradox, once per wild battle.
- Twenty actual Shiny victories produce 100% scan and materialize the correct
  variety. Tests check separate scan keys, duplicate prevention, the 200% cap,
  fleeing, lost battles, Paradox mastery separation, inventory and capacity.
- Evolution, de-digivolution, party/storage moves, feeding and save reload retain
  Shiny identity, UID, CAM, ABI and permanent training bonuses. Normal starter,
  common encounter, evolution and Season selections do not grant free Shinies.
- Real WebSocket tests cover Dawn and World DS encounters, server-authoritative
  5% scan, conversion, logout, server restart, world replication, administrative
  permissions and forged network requests. Rival materialization/counters and
  ranked saved defenders/replays retain their actual Shiny species IDs.
- All **16,040 uploaded PNGs** are installed byte-for-byte. **1,004** explicit
  animation sidecars retain the corrected normal pose and mirrored-frame mapping.
  Normal identities/art and existing Paradox mechanics remain unchanged.
- Full asset verification validates **31,414 records**. `variety_asset_verification.json`
  records variety coverage, RGBA decode checks and the absence of stale variety files.
  `asset_integrity.txt` contains the complete release hash-verification result.
- Reimport/reapplication checks preserve the 1,506-entry catalog and retained
  normal sprite fixes; the older sprite importer cannot replace v1.2.0 art.

## Visual review

`previews/` contains **18 native client captures** at **960×600** and
**1920×1080**, generated by `tools/preview_varieties_v120.py`. The preview report
records zero missing-asset errors and zero actions outside the display. The
Shiny scan, collection, battle, roster, evolution, farm and map screens and new
Paradox collection were reviewed for clipping, overlap and readable labels.
Battle layout regression tests additionally check fractional DPI, 4K, the
longest variety names and target click bounds.

These captures use clearly labelled synthetic QA account data. The battle
capture deliberately stresses multiple Shiny panels; real wild encounters
roll at most one rare replacement per battle.

## Reproduce

```sh
python tools/import_varieties_v120.py --verify --decode-images
python tools/build.py --verify-only
python -m pytest -q
```

For headless UI tests, set `SDL_VIDEODRIVER=dummy` and `SDL_AUDIODRIVER=dummy`.
Windows users can run `VERIFY_VARIETIES.bat` for the dedicated sprite check and
`BUILD_ALL.bat` to verify assets and build both native applications.
